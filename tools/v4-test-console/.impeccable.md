# NARA v4 Test Console Design Context

## Product

An internal, non-custodial Base mainnet console for the NARA protocol operator.
It makes repetitive production smoke testing easier without hiding transaction
details or pretending undeployed surfaces exist.

## Users

- Primary: the NARA protocol maintainer testing with an ordinary wallet.
- Secondary: technical reviewers validating deployment state and receipts.

## Voice and personality

Quiet, exact, technical, and candid. Use short operational language. Distinguish
live, unavailable, pending, and failed states in text as well as color.

## Visual direction

Reuse the publishable basket application's warm ivory, near-black, Base Blue,
Satoshi/Inter/IBM Plex Mono system. The console is denser and more utilitarian
than the public app, with square-edged panels, explicit status rails, and no
promotional presentation.

## Principles

1. Verify the chain, address, and deployed bytecode before enabling writes.
2. Simulate every write before opening the wallet confirmation.
3. Show exact approvals, fees, epochs, expected outputs, and transaction links.
4. Keep raw Engine positions distinct from undeployed Position NFTs.
5. Never store keys, sign automatically, or send a transaction without the
   connected wallet's explicit confirmation.
6. Use neutral action hierarchy for every value-bearing choice.
